# TOBIZ через MCP: как работать и на чём спотыкаются

Сервер `tobiz-mcp` даёт доступ к сайтам конструктора TOBIZ: 24 инструмента `tobiz_*`. Публичного
API у конструктора нет — сервер работает с внутренними эндпоинтами редактора и панели, поэтому
часть правил ниже неочевидна и выведена опытным путём.

## Справочники (читай до того, как гадать)

Разбор вендорских исходников и внутренних эндпоинтов лежит рядом со скилом. **Устанавливай скил
копированием папки** — установка по прямой ссылке на `SKILL.md` тянет только сам файл, без
справочников:

```bash
git clone https://github.com/raydev-ru/tobiz-mcp.git /tmp/tobiz-mcp
cp -r /tmp/tobiz-mcp/skills/tobiz-mcp ~/.hermes/skills/
```

| Файл | Что внутри |
| --- | --- |
| `references/block-catalog.md` | все 28 категорий и 162 типа блоков: `type_id`, название, для чего — чтобы выбрать блок под задачу, а не перебирать наугад |
| `references/block-engine.md` | как устроен движок: `values`/`cache`, каркас секции, общие поля (фон, отступы, ширина, срез, «плашка под текстом»), изображения, массивы, список всех рендереров вендора |
| `references/components.md` | кнопки (все поля, пресеты, `radius` в em, автоконтраст текста), формы (17 типов полей, маски, капча, попапы, «Спасибо»), меню (уровни через `level`, бургер, dropdown-переменные), карты, лого/телефоны/соцсети, видео, таймеры, quiz, калькулятор |
| `references/panel-api.md` | внутренние эндпоинты панели и редактора, формат ответов, коды ошибок, где лежат пресеты шрифтов и стили сайта |

## Порядок работы

1. `tobiz_list_projects` → `project_id` (если проект один, его можно не указывать).
2. `tobiz_list_pages` → `page_id` нужной страницы.
3. Понять, что уже есть: `tobiz_page_summary` (компактно) или `tobiz_list_blocks`.
4. Найти подходящий тип блока: `tobiz_search_blocks` (русский поиск по названию/описанию) →
   `tobiz_describe_block` (схема полей: имена, русские подписи, значения по умолчанию).
5. Правки: `tobiz_add_block` / `tobiz_update_block` / `tobiz_delete_block` / `tobiz_move_block`.
   Всё это живёт **в черновике** в памяти сервера.
6. Записать на сайт: `tobiz_save_page` — рендерит HTML блоков и отправляет `SaveBlocks`.
7. Проверить результат по **публичной вёрстке**: `tobiz_verify_page` (или `page_summary`).

## Что пишет сразу, а что нет

| Действие | Когда попадает на сайт |
| --- | --- |
| правки блоков (`add`/`update`/`delete`/`move`) | только после `tobiz_save_page` |
| `tobiz_save_page` | сразу (рендер + `SaveBlocks`) |
| `tobiz_update_page` (SEO, название, slug, og:image, доступ) | сразу |
| `tobiz_copy_page`, `tobiz_delete_page` | сразу (`delete_page` требует `confirm=true`) |
| `tobiz_upload_image`, `tobiz_set_block_image` | сразу (файл загружается на сервер) |

## Грабли (каждая проверена на живом сайте)

1. **Без `tobiz_save_page` на сайте ничего не изменится.** Сервер хранит HTML блока, а не «поля»,
   поэтому сохранение само рендерит HTML шаблонами вендора. Если рендер не удался — сохранение
   падает с `RENDER_FAILED`, и это лучше, чем записать пустой блок.
2. **Идентификаторы передавай как удобно** — числа принимаются (`project_id: 432549`) наравне
   со строками. Но **тип блока — это `type_id`**, а не `block_type_id`: при опечатке вернётся
   `UNKNOWN_TYPE` с пустым значением, что легко принять за «блока нет в сборке».
3. **`select`-поля принимают строку** (`mode: "3"`, а не `3`) — иначе `BAD_ARGUMENT`.
4. **Массивы контента (`arr1`, `arr2`, `menu1`, `form1`) задаются целиком.** Сколько элементов
   передал — столько и останется; чтобы удалить пункт, передай укороченный список.
5. **Дефолты вендора надо перезаписывать.** Новый блок приходит с демо-текстами («Плиточные
   работы», «Тариф М», «Замеры с ювелирной точностью»), демо-картинками и телефоном
   `+7 800 333 22 33`. Они живут в тех же полях, что и рабочий контент, и попадают на сайт,
   если их не тронуть. После сборки страницы полезно свериться с публичной вёрсткой на предмет
   таких остатков.
6. **`tobiz_upload_image` требует `block_id` реального блока этой страницы**: без него конструктор
   отвечает «Изображение не загружено! #2», с посторонним id — `#3`. Сервис сам отсекает вызов
   без `block_id`. Картинки, доступные для страницы, можно подсмотреть в
   `tobiz_page_info` → `page_image_options`.
7. **Параметры страницы читай через `tobiz_page_info`**, а не по ответу редактора:
   `window.tobiz` может отдавать устаревшие значения (мы на этом уже попались).
8. **`tobiz_update_page` отправляет форму целиком** — так устроена панель (`action=edit_page`).
   Инструмент сам делает «прочитал → подменил → отправил → перечитал и сверил», а недоведённые
   поля возвращает в `mismatched`. Если что-то не применилось — смотри `mismatched`, а не верь
   `status: OK`.
9. **SEO дублируется в `SaveBlocks`**: после правки SEO через `update_page` не сохраняй страницу
   из старого черновика — сначала перечитай (`page_summary`/`page_info`).
10. **Радиус кнопок задаётся полем `radius` в `em`**, и рендерер выводит его инлайн-стилем
    (`border-radius: <radius>em`) — инлайн перекрывает вендорское правило
    `.btn1.surround{border-radius:2px}`. Поэтому считай значение от шрифта кнопки:
    `radius = 7 / font_size_px` (0.35 при 20px, 0.389 при 18px, 0.412 при 17px дают ровно 7px).
    Пресет `style` тоже задаёт радиус, но поле `radius` его перекрывает. Проверка — вычисленный
    `border-radius` в браузере, а не «на глаз».
11. **Цвет текста кнопок внутри форм полем не задаётся** — работает `var(--autocontrast-text-color)`:
    светлый фон кнопки → тёмный текст, тёмный → белый. Поэтому тёмно-зелёная кнопка получает белый
    текст сама, а вендорские жёлтая и оранжевая — чёрный. Меняешь фон кнопки — перепроверь
    вычисленный `color`.
12. **Меняй модель блока и перерисовывай, а не подпирай CSS.** Блок «Пользовательский код»
    (type 163) со своими правилами и `!important` — крайнее средство: он расходится с настройками
    в редакторе (в полях останется одно, на сайте другое) и легко забывается. Правка полей +
    `tobiz_save_page` даёт тот же результат честно.
13. **`?v=<число>` в публичном URL — это id страницы.** Не добавляй свои query-параметры с `v`
    (`?v=2` отдаёт 404). Для обхода кеша подойдут любые другие параметры.
14. **Архивные и flex-блоки правятся частично** — если тип помечен как архивный или у него нет
    шаблона, меняй только значения верхнего уровня и проверяй результат.
15. **Работай на отдельном сайте.** Правки блоков и SEO уходят на прод-страницу сразу;
    для экспериментов — `TOBIZ_READ_ONLY=1` и отдельный проект.

## Красивый UI: как получить и с чего начать

Стиль задаёт не вёрстка, а решения: один оффер, один целевой действие, одна типографическая шкала.
Для этого скил работает в паре с **`landing-page-design`** (система из реестра skills.sh,
источник `elayadesign/ai-design-skills`):

```bash
hermes skills install https://raw.githubusercontent.com/elayadesign/ai-design-skills/main/skills/landing-page-design/SKILL.md --category design
```

Порядок применения внутри TOBIZ:

1. **Структура и копирайт — по `landing-page-design`** (оффер, заголовки, доказательства, CTA,
   SEO-блок). Это дешевле и важнее цветов.
2. **Секции — из каталога блоков.** Не подгоняй неподходящий блок: в `references/block-catalog.md`
   под каждую задачу есть 3–5 вариантов (обложки, преимущества, тарифы, отзывы, форма, подвал).
3. **Визуальные правила — полями блоков, а не CSS:** фон и отступы (`bg*`, `padd_top`/`padd_bottom`),
   ширина контейнера (`inner_width`), скругление и цвета кнопок (`style`/`radius`, `color`, `text_color`),
   радиус и границы карточек — в самом блоке; шрифты — пресетами сайта (`/json/stylesFontsPresets.json`).
   Единая палитра на страницу: подбери 2–3 цвета, выстави их в каждом блоке — так редактор и сайт
   не разойдутся.
4. **Проверяй контраст вычисленным цветом** (текст на фоне, автоконтраст кнопок), а не на глаз:
   у вендора есть и белый текст «по умолчанию», и белые подписи на светлых фонах.
5. **Свой HTML/CSS — только в крайнем случае** и осознанно: блок «Пользовательский код» (type 163)
   или `replace_form_html` расходится с настройками редактора и переживает ваши правки. Сначала
   исчерпай поля блока.

## Проверка результата

`status: OK` от конструктора не означает, что на сайте то, что нужно. Всегда проверяй вёрстку:

* `tobiz_verify_page` с `expect=[...]` — есть ли тексты в публичной вёрстке;
* `tobiz_page_summary` — состав блоков и порядок;
* для стилей (цвета, радиусы, скрытые попап-формы) — открыть страницу браузером и посмотреть
  `getComputedStyle`: у скрытых элементов стили всё равно читаются, а в разметке их не видно.

## Короткие рецепты

* **Собрать секцию**: `search_blocks` («тарифы», «обзор», «отзывы») → `describe_block` →
  `add_block` с `values` → `save_page` → `verify_page`.
* **Поправить текст**: `list_blocks` → `get_block` (или `describe_block only=changed`) →
  `update_block` с новыми полями → `save_page`.
* **Прописать SEO**: `page_info` → `update_page(seo_title=…, seo_description=…, seo_keywords=…,
  og_image=…)` → проверить `<title>` и `meta` в публичной вёрстке.
* **Залить лого и подставить**: `upload_image(block_id=<реальный блок>, path=…)` → взять
  `filename` → `update_block`/`update_page(og_image=…)`.
* **Дублировать страницу**: `copy_page` (`apply=false` — сначала посмотреть план и доступные
  проекты) → `delete_page(confirm=true)` для уборки лишнего.

## Экономия контекста

* `tobiz_page_summary` вместо `tobiz_list_blocks` — карта страницы вместо полных значений.
* `tobiz_describe_block(only="changed")` — только поля, отличающиеся от дефолта.
* `tobiz_search_blocks(limit=…)` — библиотека большая (162 типа), не выгружай её целиком.

## Если что-то сломалось

* `AUTH_FAILED` / `AUTH_CAPTCHA` — сессия конструктора недействительна; положи в том сессии
  файл `cookies.json` (достаточно пары cookie `session` + `email`) или задай `TOBIZ_EMAIL`
  и `TOBIZ_PASSWORD`.
* `RENDER_FAILED` — блок не отрендерился; проверь `type_id` и значения полей (частая причина —
  значение не из списка допустимых).
* `UPSTREAM_UNAVAILABLE` — конструктор не ответил; повтори запрос, черновик в памяти сохраняется.
